#
# `AppError::sanitized_message()` passes `ErrorCode::PermissionDenied` messages
# through verbatim: the refusal a handler writes is exactly what the athlete,
# the coach or the admin token holder reads. Every line below has been read and
# confirmed safe to show the person who was refused — it names what was refused
# and nothing else. Adding a line means you have read yours and made that call:
#
#   - no table or column name, no schema detail
#   - no id, key or path the caller did not already hold
#   - no operator-only fact, and nothing about another principal
#   - it says what was refused, so there is a next action
#
# The scanner reads three construction shapes — `AppError::new(...)`,
# `Self::new(...)`, and `error_helpers::user_state_error(...)`, which prefixes
# "User state error: ". A `format!` message keeps its placeholders, because the
# shape is what gets reviewed; a `&str` constant is resolved to its value, so
# changing the constant fails this gate rather than slipping past it.
#
# Three entries below reach an admin-token holder only, and each names something
# about that caller's OWN token — the permission it lacks, the permission set it
# carries, the tenant it is scoped to. That is the caller's own scope, the same
# thing an OAuth `insufficient_scope` challenge names, not a cross-principal
# leak. Nothing here reaches an athlete on an admin path.
#
